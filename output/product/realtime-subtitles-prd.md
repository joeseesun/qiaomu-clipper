# 乔木剪藏 · 无字幕视频学习 PRD

版本：0.1；日期：2026-10-05；状态：设计方案，待技术验证。基于 main 1.11.2 与 PR #33 审查结果。文中数值为验收目标，均不是已测性能。

## AI 速读卡

- 产品一句话：让没有字幕的视频也能边看、边读中文、边保存理解。
- 核心循环：进入学习页 → 开启生成字幕 → 阅读双语 → 点击回看 → 剪藏或写学习笔记。
- 目标平台：首版 Chrome 桌面，YouTube / B 站学习页。
- 硬约束：用户主动取音；一个播放源、一个当前字幕来源；保留原文、真实时间戳和覆盖范围。
- 推荐默认：浏览器本地 Whisper；稳定句子自动提交并翻译；共享取音作为捕获失败后的替代入口。
- 发挥空间：状态文案、字幕排版、可访问性细节、模型选择与调度实现。
- P0 验收：一条无字幕视频连续观看 20 分钟，声音正常、原文与译文持续出现、可回看和保存。
- 最容易翻车：捕获错标签页、翻译晚到后字幕消失、跳转后串词、旧配置失效、静默丢音频。
- 超预期机会：二次回看直接使用已有字幕；原文修正后只重译该句；笔记自动带回看时间。

## 第一章：产品概述

乔木剪藏的无字幕视频学习是一项视频阅读能力，让自学者把正在听的内容变成双语文稿，并保存自己的理解，减少暂停、听写和另开翻译工具的步骤。

### 1.1 差异化对比表

只比较已查到的公开工作流，不声称其他产品均不支持某项能力。

| 功能 | 竞品或公开方案 | 本产品 | 实现方式 |
|---|---|---|---|
| 浏览器本地识别 | Hugging Face 示例展示麦克风识别与模型运行 | 识别正在学习的视频，结果进入既有阅读流程 | 捕获适配器 + 字幕数据层 + 现有学习页 |
| 取音后的使用链路 | Chrome 官方示例以录制和下载为目的 | 同时服务双语阅读、回看、AI 与 Obsidian 保存 | 同一当前字幕数据服务多个输出 |
| 本地服务依赖 | WhisperLiveKit 以服务及流式接口为主要形态 | 浏览器运行作为默认，本地服务为后续可选增强 | 可替换识别后端，产品操作保持一致 |

对应资料：Hugging Face 的实时示例使用 Worker、WebGPU 和可复用模型实例；Chrome 官方给出后台捕获方案；WhisperLiveKit 提供流式识别和翻译接口。这些证明组成能力存在，不证明本项目已满足延迟目标。

### 1.2 三类用户画像

| 角色 | 核心目标 | 当前最大摩擦 | 愿意使用的一个功能 |
|---|---|---|---|
| 外语课程学习者 | 听懂观点并回看难句 | 无字幕时反复暂停查词 | 原文与中文紧凑对照，点击句子回看 |
| 访谈与播客学习者 | 长时间听内容并积累理解 | 片段听完后找不回原位置 | 学习笔记带视频时间链接 |
| B 站专业内容学习者 | 提取没有字幕的讲解 | 人名和术语听不清 | 留存可核对的识别原文，后续支持修正 |

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 已播放音频的增量识别与中文翻译 | 从取音直接得到尚未播放的完整字幕：没有音频输入 |
| 首版 Chrome 桌面学习页 | Firefox / Safari 实时取音：需要分别验证，不能沿用 Chrome 假设 |
| 稳定原文入文稿，译文随后补上 | 零延迟同声字幕：识别和翻译都需要输入与计算时间 |
| 用户选择本地识别，文字发送给其翻译模型 | 自动上传音频到云服务：首版不引入这条路径 |
| 语音语言默认自动检测，允许手动纠正 | 自动检测一定正确、模型一定听懂术语：需要测试和纠正入口 |
| 平台字幕失败后用户仍可开启识别 | 将接口阻断误报为视频没有字幕：必须分开描述 |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| 原播放器进入即显示；字幕失败不重建播放器 | 平台字幕优先，Whisper 由用户开启 | 控件组合与空状态表达 |
| 同一时刻一个可听播放源、一个当前字幕来源 | 首版一条识别会话，第二条启动时提示停止前一条 | 服务端并发实现留后续 |
| 稳定字幕自动保存；不逐段要求确认 | 实时字幕局部更新，学习文稿增量追加 | 微动画与显示节奏 |
| 音频仅用于本地识别；首次翻译前说明文字去向 | 译文只关联明确的原文版本 | 模型自检和术语提示 |
| 不以 DOM 或段落下标作为字幕主键 | 延续项目现有 TypeScript / webpack / Lucide | 内部文件布局 |
| 模型加载前用户可以正常看视频 | 模型按需下载，加载期间提示“就绪后开始生成” | 在有明确证据时优化预热 |

推荐默认：字幕覆盖层原文一行、译文一行，长句按语义分页；学习文稿保留完整句子。小屏上下排列，AI 分栏沿用既有行为。复制、下载、剪藏留在顶栏，不另建 Whisper 操作工具栏。

菜单层级：

```text

+-- 来源：平台字幕 / 自动生成字幕
+-- 识别语言：自动 / 中文 / 英文 / 其他支持语言
+-- 显示：双语 / 原文 / 中文

+-- 清除生成字幕
```

“中文翻译”开关关闭时保留原文；语言设置放在更多或原有设置入口。AI、复制和剪藏读同一当前来源的稳定字幕。

## 第三章：核心模块详细设计

### 第 3.1 节 字幕发现与主动开启

#### a) ASCII 图

```text
+----------------------------------------------------+
| 正在寻找字幕… 视频可以先播放                       |
| 未找到可用字幕  →  生成字幕                         |
| 字幕加载失败    →  重试 / 生成字幕                  |
| 已有平台字幕    →  中文翻译开关                     |
+----------------------------------------------------+
```

#### b) 交互流程

```text
进入学习页 --> 显示播放器 --> 异步查字幕
  +-- 成功 --> 使用平台字幕
  +-- 可靠空结果 --> 提供生成字幕
  +-- 登录或接口失败 --> 提供重试和生成字幕，保留具体故障原因
生成字幕 --> 检测环境与模型 --> 用户取音 --> 从播放器当前位置识别
  +-- 无可用推理后端 --> 显示当前环境不可用，保留平台字幕流程
  +-- 模型下载失败 --> 原地重试，不中断视频
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| searching | 查找字幕 | 局部“寻找字幕” | 成功、空结果或失败 |
| native-ready | 可用平台字幕 | 默认文稿 | 用户切换来源 |
| unavailable | 可靠空结果 | 生成字幕入口 | 用户开启或重试成功 |
| fetch-error | 接口失败 | 故障原因和重试 | 重试或开启识别 |
| model-loading | 首次加载或预热 | 阶段与下载进度 | 模型就绪或失败 |
| model-error | 下载、校验或推理启动失败 | 重试 | 用户重试成功 |

#### d) 依赖关系

读 videoKey、平台字幕响应、浏览器能力和本地缓存；写当前来源、模型状态与识别意图。模型就绪之前不开始无限积累音频，界面明确“就绪后开始生成”。

#### e) 待决问题

技术验证后决定首发默认 Whisper 模型；暂按 multilingual tiny / base 两档比较，不承诺哪一档达到目标。

### 第 3.2 节 音频会话与播放器时间

#### a) ASCII 图

```text
+----------------------------------------------------+
| 就绪：开始生成字幕                                 |
| 授权：点击扩展图标开启，或选择当前页共享声音         |
| 运行：正在生成 · 已生成至 03:18        停止          |
| 暂停：视频已暂停，字幕将随播放继续                   |
| 失败：未获得页面声音                  重新开启      |
+----------------------------------------------------+
```

#### b) 交互流程

```text
用户开启 --> 校验目标 tab / videoKey --> 获得流 --> 保留声音输出 --> 收音
  +-- 授权不足 --> 一次明确授权入口；用户可选共享声音兜底
  +-- 没有音轨或选错页 --> 立即释放流并重选
收音 --> 同步播放器时钟 --> 有语音才提交识别
  +-- 时钟失联 --> 暂停提交字幕，显示等待播放器恢复
  +-- 跳转 / 倍速切换 --> 结束旧音频窗口，递增 epoch，创建新时间锚点
停止 --> 停取音 --> 有效尾部有界处理 --> 保留结果 --> 释放资源
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| capture-idle | 模型已就绪 | 开始按钮 | 用户开启 |
| needs-authorization | 当前目标缺授权 | 简短授权入口 | 授权或取消 |
| capturing | 流、时钟均有效 | 正在生成和停止图标 | 暂停、停止或故障 |
| paused | 播放器暂停/缓冲/广告 | 等待视频继续 | 正常内容恢复 |
| clock-lost | 时钟超过 1 秒未更新 | 等待播放器 | 恢复或重新开启 |
| draining | 主动停止且尚有有效尾部 | 正在处理最后片段 | 处理完成、超时或用户取消 |
| capture-error | 流结束或音轨缺失 | 原因和重试 | 用户重启 |

#### d) 依赖关系

播放器适配器读 currentTime、playbackRate、paused、seeking、adState；捕获服务绑定 captureTabId、videoKey、sessionId。每一音频段携带 epoch 和独立时间映射。媒体时间 = 锚点媒体时间 + 有效音频时长 × 当时倍速；跨跳转、缓冲或倍速变化必须切段，不能全程套一个 offset。

暂停不处理新增静音；广告状态可检测时排除广告。平台无法可靠提供广告/播放器时钟时，显示能力限制并暂停生成，不能编造时间。关闭拥有会话的学习页后停止取音；刷新后恢复已存文稿，但取音由用户重新开启。导航到不同视频立即结束旧会话。

停止后尾部处理最多等待 10 秒，超时保留稳定结果，并标记尾部未完成。生成中播放区间及未识别原因分别记录：跳过、过载、时钟失联、识别失败；正常静音不算漏段。

#### e) 待决问题

学习页 extension URL 的 tabCapture 授权链路与 B 站内嵌时钟需实测；若主链路不成立，首版保留共享当前学习页声音，不能偷偷改为收听另一页面。

### 第 3.3 节 字幕生成与展示

#### a) ASCII 图

```text
+----------------------------------------------------+
| 播放器下沿：                                       |
| We learn by doing.                                 |
| 我们通过实践学习。                                 |
+----------------------------------------------------+
| 文稿：                                             |
| 01:24  We learn by doing.                           |
|        我们通过实践学习。                          |
| 01:29  The next…   （识别中，仅尾句可变化）          |
+----------------------------------------------------+
```

#### b) 交互流程

```text
有效音频 --> VAD / 重叠窗口 --> 临时文本 --> 稳定判定 --> 自动入文稿
  +-- 静音 --> 不生成文字，继续等待
  +-- 推理失败 --> 标记该区间，保留已有文稿，允许恢复
稳定文本 --> 翻译 / 搜索 / 导出 / AI
  +-- 原字幕晚到 --> 提示可切换，不抢占当前来源
  +-- 处理过载 --> 显示落后并合并待处理窗口，达到上限时暂停生成
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| waiting-speech | 无有效语音 | 等待视频语音 | 检测语音 |
| partial | 尚未稳定 | 尾句弱化，无持续闪动 | 稳定或被修订 |
| committed | 重复识别一致或有效句边界确认 | 正常原文 | 用户修改或来源切换 |
| lagging | 待处理语音持续积压 | 状态行显示延迟 | 追上或暂停 |
| gap | 有效语音未成功识别 | 文稿时间范围提示缺失 | 明确补录或保留缺失 |
| native-available | 平台字幕晚到 | 局部“原字幕已可用” | 用户切换或忽略 |

#### d) 依赖关系

识别 Worker 写 partial / commit / error 事件；SubtitleStore 是唯一权威数据源，展示只消费数据。滚动窗口保留重叠区，按稳定前缀去重，不能把固定块结果直接拼接。连续两次更新一致可作为首个稳定策略，句边界与强制尾段策略必须通过夹具验证。

实时覆盖层展示最新生成的稳定句子；同一句译文晚到时补入，不因此更换句子。旧句的迟到译文只进入文稿，不覆盖新句。跳转时立即清空覆盖层，epoch 不一致的迟到事件丢弃。静音时最后一条字幕最多展示 6 秒后淡出，字幕和播放器控制区不互相遮挡。

回看已有片段时采用真实视频时间匹配缓存字幕；未覆盖片段才继续识别。首版文稿跟随字幕生成；用户手动滚动后停止自动跟随，10 秒无手动交互后恢复，沿用原有交互约定。

源切换是原子操作：更新 activeSourceId，一次重绘当前文稿、更新翻译订阅、重新绑定时间跳转。另一个来源保留在数据层，不创建第二份同时参与导出/AI 的字幕 DOM。

#### e) 待决问题

无。实时与回看采用不同显示策略属于硬约束，具体稳定前缀算法属于推荐默认。

### 第 3.4 节 增量翻译与学习输出

#### a) ASCII 图

```text
+----------------------------------------------------+
| 中文翻译：开                                       |
| 01:24  We learn by doing.                           |
|        我们通过实践学习。                          |
| 01:29  The next step is to practice.                |
|        正在翻译… / 翻译失败，重试                  |
| 顶栏：复制 / 下载 / 剪藏 / AI                      |
+----------------------------------------------------+
```

#### b) 交互流程

```text
稳定原文 --> 合并待译短句 --> 携带邻句上下文 --> 翻译模型 --> 校验 ID --> 写缓存
  +-- 未配置模型 --> 继续生成原文，引导原有 AI 设置
  +-- 网络错误 / 输出缺项 --> 保留原文，单句失败并有界重试
切换目标语言 --> 取消旧语言请求 --> 读取匹配缓存或新建任务
  +-- 原文修订 --> 仅受影响句子与必要邻句失效
  +-- 导出时译文未齐 --> 导出已有内容并标记未完成，不阻塞无限等待
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| translation-off | 用户关闭 | 仅原文 | 用户开启 |
| queued | 稳定句待译 | 局部等待 | 请求开始 |
| translating | 请求处理中 | 局部正在翻译 | 成功或失败 |
| translated | 校验通过 | 对照译文 | 原文版本变化或切换语言 |
| translation-error | 超时、网络或协议错误 | 单句重试 | 成功或用户忽略 |
| no-model | 无可用模型 | 配置入口 | 保存模型配置 |
| export-snapshot | 用户复制/下载/保存 | 输出结果 | 完成或重试 |

#### d) 依赖关系

读当前来源稳定 cue、目标语言、模型设置；写 TranslationStore。首版同一会话翻译请求并发 1；最多合并 3 个已稳定短句，等待合并不超过 500ms，已有长句立即发送。请求附带最多两个已知邻句供上下文，不等待未来语音。要求逐 cueId 返回完整译文；JSON 未完成时不将 token 直接当作正式字幕。流式译文预览为后续优化。

翻译模型选择：有效的显式 translationModel → 老版 qiaomuChatModel 对应可用模型 → 首个已启用且服务有效的模型 → 无模型引导。显式模型失效时提示使用哪个回退模型，避免悄悄换供应商。读取兼容规则不覆盖用户既有设置，首次保存才写新字段。

缓存键包含 cueId、textRevision、targetLanguage、provider/model、translationPolicyVersion。原文与译文严格分离，模型不得改时间戳或替代原文。开关关闭时取消请求、隐藏译文、保留缓存；重开时复用匹配结果。单次请求超时推荐 15 秒；网络故障自动重试最多 2 次，退避 1 秒、3 秒；鉴权失败不自动重试。输出缺项只补请求缺失句，重试耗尽后显示单句错误，其余句子继续处理。

复制、AI、剪藏均取当前来源的稳定文稿快照。复制原文为默认，双语在更多中选择；原文与双语下载分别命名。自动生成内容明确标识来源与已覆盖范围。学习笔记继续采用既有独立幂等日记追加通道，不走 RSS 投稿。

#### e) 待决问题

无。首版使用完整句翻译；真正逐词译文需要单独评估稳定性、成本及支持模型。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 同一份字幕贯通观看和学习

结构性判断：基于公开信息的推断，录制示例关注音视频文件，识别示例关注模型运行，两者的数据生命周期未必包括视频回看、知识保存与日记追加。本产品已有学习页和保存流程，可把新字幕接入同一文稿数据层，而非另建字幕应用。

```text
看视频 --> 原文和译文 --> 选择一句 --> 回看 / 问 AI / 写理解 --> 保存到 Obsidian
```

风险与应对：AI 可能把已识别片段当作全片；上下文首行声明“仅覆盖 01:20–08:45”，不得回答未覆盖片段的具体内容。

### 第 4.2 节 生成结果可以复用

结构性判断：实时服务关注当前音频，稳定媒体身份与倍速时间映射需要额外实现。首版建立 videoKey + 来源 + cue 的数据契约，为再次观看复用铺路；具体跨会话覆盖范围调度列入后续。

```text
回到已生成片段 --> 命中缓存 --> 按视频时间显示 --> 未生成范围才开启新识别
```

风险与应对：B 站分 P 和 YouTube 不同视频不得共用缓存；媒体替换、模型变化及用户清除需独立记录。

### 第 4.3 节 超预期机会

以下不扩大首版闭环，进入对应后续优先级：

1. 选中字幕写笔记时，自动携带回看链接和该句原文。
2. 再次进入同一视频，直接显示上次生成的文稿与译文。
3. 用户修正人名后，仅重译相关句子，并将术语用于当前视频后续翻译。

持久化使用项目已有存储机制或 IndexedDB；稳定 cue 及译文在增量提交时保存，临时音频仅驻内存。默认缓存 30 天、字幕及译文总容量上限 100MB，超限先提示并淘汰最久未访问的视频缓存；不删除已经保存到 Obsidian 的内容。识别结束不保存原始音频；模型缓存与字幕缓存单独管理，清除文稿不能误删模型。

## 第六章：技术架构

```text
既有学习界面：播放器 / 双语文稿 / 顶栏 / AI / 学习笔记
             | 命令与订阅
字幕会话层：唯一当前来源、状态机、视频身份、覆盖区间
             | 数据事件
SubtitleStore / TranslationStore：版本、去重、缓存、持久化
             |                       |
ASR 适配器：partial / commit       翻译调度：稳定句、重试、缓存
             |                       |
识别 Worker：模型、VAD、滚动窗口   现有 streamChat 服务调用
             |
Offscreen Document：音频流、AudioWorklet、输出声音、时钟配对
             |
捕获适配器：tabCapture 优先 / getDisplayMedia 可见兜底
             |
播放器适配器：YouTube / B 站媒体时钟、跳转、倍速、广告
```

Service Worker 管理捕获启动和消息路由，不承担音频推理循环；持续音频处理由 Offscreen Document 与独立 Worker 承担。首次创建与销毁需有互斥和会话引用，首版只允许一个捕获会话。

| 库名或接口 | 用途 | 为何优于替代方案 | 大致包体积 |
|---|---|---|---|
| Chrome tabCapture + offscreen | 指定标签页后台取音 | 满足授权条件时省去共享选择框，捕获不依赖弹窗常驻 | 浏览器内置 |
| getDisplayMedia | 取音失败后的用户可见兜底 | 用户明确选择当前页面，适用于主授权路径不成立 | 浏览器内置 |
| AudioWorklet | 连续 PCM 与本地音频输出 | 音频处理与界面主线程解耦 | 项目实现待测 |
| Transformers.js / ONNX Runtime Web | 浏览器本地 Whisper | 与 PR 已引入的方向一致，可评估 WebGPU/WASM | 未知；以最终 ZIP 和资源清单实测 |
| Silero VAD 或等效 VAD | 有效语音检测 | 比仅用音量阈值更能区分语音与部分非语音，仍须夹具验证 | 未知 |
| 既有 streamChat | 文本翻译 | 复用凭证存储、服务配置及调用路径 | 不新增独立供应商 SDK |
| WhisperLiveKit（后续） | 本地服务增强 | 提供流式后端及适配层，适合较大模型实验 | 未知；另安装，不计入扩展 ZIP |

已验证的平台事实：tabCapture 需要用户调用扩展及符合条件的目标授权；后台流 ID 到 offscreen 的链路支持 Chrome 116+；捕获后需要保持声音输出。依据 Chrome 官方文档。最主要的风险是学习页捕获授权与实际音源身份，必须先做真实学习页技术验证。

Whisper Streaming 说明固定短块拼接有断词与稳定性问题，LocalAgreement 可以作为滚动识别确认策略；本产品借鉴协议与判定原则，不直接把 Python 流式工程塞进浏览器。

可替换技术原则：推荐 Transformers.js 浏览器后端；若实际设备测试未达标，可用本地 WhisperLiveKit / whisper.cpp 替换识别实现。不可变的是音源身份、媒体时间、稳定 cue、原文版本、当前来源及用户主动启动契约。WASM 只能作为能力候选，未达吞吐门槛时显示当前设备不可用，不保证实时。

运行时脚本、Worker、WASM 与 ONNX 执行模块需要按扩展规则打包；模型权重可按需下载，但代码不得改成 CDN 动态执行。打包与商店政策验证应独立于模型识别验证。

### 7.1 键盘快捷键

| 操作 | 快捷键 | 备注 |
|---|---|---|
| 进入学习页 | 沿用 aaa | 不保证此入口本身授予 tabCapture 能力 |
| 写学习笔记 | 沿用 N | 输入框与文本选择时不抢键 |

### 7.2 右键菜单与上下文菜单

首版不覆盖浏览器原生右键。既有选中文字操作与字幕更多菜单补充：

```text
选中稳定字幕
+-- 复制原文
+-- 复制双语（有对应译文时）
+-- 写入学习笔记
+-- 回看这一句
```

### 7.3 空状态

无字幕：“未找到可用字幕”，动作“生成字幕”；接口失败：“字幕加载失败”，动作“重试 / 生成字幕”；无语音：“等待视频语音”；无翻译模型：“原文正在生成，配置模型后可翻译”。译文开关无模型时允许说明和配置入口，不能使原文生成失败。

### 7.4 错误状态

| 触发条件 | 用户可见提示信息 | 恢复操作 |
|---|---|---|
| 未获得捕获授权 | 需要开启当前页面声音读取 | 点击扩展入口，或主动选择共享声音 |
| 共享错误页面 / 缺音轨 | 未获得当前视频的声音 | 释放流，重新选择当前学习页 |
| 模型下载或后端失败 | 字幕模型加载失败 | 重试；已缓存模型可用则复用 |
| 翻译请求超时 | 此句翻译失败，原文已保留 | 单句重试；不重跑识别 |
| 识别或翻译持续落后 | 处理已落后，可暂停视频等待 | 用户选择暂停视频追赶，或停止生成；不自动改播放速度 |

### 7.5 加载状态

动作反馈应在 100ms 内显示；小于 200ms 的缓存读取不显示转圈。模型加载显示下载阶段及进度，未知总量只显示阶段；取音授权显示等待用户操作。翻译状态放在对应句，不占用播放器中央。暂停视频追赶为用户主动动作；停止生成不暂停视频。

高频按钮使用 Lucide 图标、tooltip、accessible name；主空状态“生成字幕”可保留文字。焦点不造成双边框、厚重光晕或布局位移。动态文稿不能整页 aria-live 播报，状态区使用节制的 role=status。

### 8.1 支持的输出格式

## 第十章：性能指标

以下为首发门槛与测试目标。测试两台参考设备：Apple Silicon Mac 16GB；Windows 集显笔记本 16GB，记录实际型号、Chrome 版本、模型、WebGPU/WASM 和网络。以 1× 播放为首发门槛；1.5× / 2× 另外报告，不把其结果混入 1× 指标。模型下载单列，不计入热启动延迟。

| 指标名称 | 目标值 | 测量方法 | 劣化阈值 |
|---|---:|---|---:|
| 控件响应 | p95 ≤ 100ms | click 到状态 paint 的 Performance 记录 | > 200ms |
| 热启动开始收音 | p95 ≤ 2 秒 | 用户授权完成到首个有效 PCM 包；20 次 | > 5 秒 |
| 原文提交延迟 | p50 ≤ 3 秒；p95 ≤ 6 秒 | 人工标注语义片段末尾到稳定 cue 到达；至少 100 段 | p95 > 8 秒 |
| 双语完整出现延迟 | p50 ≤ 5 秒；p95 ≤ 10 秒 | 同一语义末尾到对应译文校验后 paint | p95 > 12 秒 |
| 推理吞吐 | 平均实时因子 ≤ 0.7 | 20 分钟识别总处理时间 / 有效输入音频时长 | 连续 30 秒 > 1.0 |
| 未处理音频上限 | ≤ 30 秒 | 测量尚未提交处理的有效输入时长 | ≥ 30 秒暂停生成并记录缺失 |
| 媒体时钟断联 | ≤ 1 秒判定 | 停止时钟消息，测提交暂停时间 | > 2 秒仍提交新 cue |
| 时间戳误差 | 中位数 ≤ 0.5 秒；p95 ≤ 1.5 秒 | 100 个语义片段与人工标注比较 | p95 > 2 秒 |
| 音轨关闭 | 用户停止后 ≤ 1 秒 | track.readyState 与捕获状态记录 | > 2 秒 |
| 英语原文识别误差 | WER ≤ 20% | 干净英语口语夹具 20 分钟，固定文本正规化 | > 30% |
| 中文原文识别误差 | CER ≤ 20% | 普通话夹具 20 分钟，固定标点正规化 | > 30% |
| 翻译可用性 | ≥ 90% 句子保留核心意思，无关键否定/数字错误 | 100 句人工盲评，错误类别逐条记录 | < 80% |
| 过载触发 | 积压 > 10 秒持续 10 秒时提示 | 人工降低推理速度并验证状态 | 静默落后超过 20 秒 |
| 首版连续会话 | 20 分钟，0 次串视频、错 epoch 提交及字幕源混合 | 视频身份与事件日志，核验导出 | 任意 1 次 |
| 停止后的尾部等待 | ≤ 10 秒 | 停止到 draining 完成；慢设备注入 | > 10 秒仍显示无限等待 |
| 本地文稿落盘 | 稳定事件后 ≤ 1 秒；重载丢失 ≤ 1 秒已提交内容 | 故障注入后核查存储与恢复 | 丢失 > 2 秒 |

单次首次模型下载时间由实际网络决定，界面记录阶段、字节数与失败原因；不设置无法保证的固定首下载秒数。任何设备未达到吞吐门槛，不将该配置标为支持实时。识别模型耗时之外，翻译供应商延迟必须单独统计。

## 第十一章：开发者交接说明

### a) 实现顺序建议

你先验证真实学习页的音频捕获，不先做完整设置页。让用户一次明确开启后，确认捕获的是正在播放的视频、声音正常、20 分钟流持续可用、停止确实释放；主授权失败时共享兜底也必须在同一播放页成立。

你随后建立 SubtitleStore、事件版本与播放器时间映射，再接浏览器识别 Worker；用确定性音频和时钟夹具验证跳转、静音、倍速与迟到事件。最后改造现有翻译为数据订阅式增量调度，并将复制、AI、剪藏接到当前来源快照。

发布验证分三道门：第一道是真实页面捕获与声音保留；第二道是模型真实加载、有效时间映射与持续吞吐；第三道是增量翻译、旧配置及学习输出。保留既有平台字幕路径，新的生成能力由独立开关启停；某道门失败不得用其他道门的测试结果宣称整条链路可用。首发只标明经过验证的设备与浏览器范围。

当前 youtube-translation.ts 在 mount 时抓取全部字幕 DOM 并固定 batches，是静态文稿流程；你不能依靠不停重新 mount 给它补实时字幕。保留原功能，通过新的调度接口支持动态 cue。PR #33 的独立模块可复用，字幕重复、队列误删和翻译模型迁移问题必须先消除，不整体照搬设置改版。

### b) 最可能导致返工的三个决策

| 决策 | 安全的默认选择 | 改变方向的信号 |
|---|---|---|
| 取音目标与授权 | 绑定实际播放的学习页；tabCapture 技术验证后启用，共享为可见兜底 | extension URL 或现有入口无法满足授权；不得假称无弹窗可用 |
| 字幕权威数据 | videoKey + sourceId + cueId + revision；只渲染一个当前来源 | 原字幕和识别结果同时参与 AI/导出，说明数据层仍未统一 |
| 本地模型配置 | 用目标设备实测 tiny / base，按吞吐与识别误差选择 | 主流目标设备实时因子持续 ≥ 1 或质量不达标，则调整模型或后端 |

### c) 哪里要严格，哪里可以灵活

第一、三、五、八章的音源、时间、数据与输出语义是约束；第十章是候选首发门槛，只有在记录测试证据并明确设备范围后才能修订。第二、六、七章布局、实现库与文案是建议，允许沿用项目既有组件。第四、九章的后续机会不能倒灌进首版范围。

### d) 已知的未知项

- 未验证：学习页 extension URL 的 tabCapture 授权与实际取音；进入学习页的 aaa 不应被视为已获得授权。
- 未验证：B 站不同内嵌播放器版本的媒体时钟、广告识别与倍速行为；跳转重载后需要恢复能力检测。
- 未验证：两个参考设备上的模型质量、资源占用、首加载体积、持续吞吐和翻译供应商延迟。
- 未验证：兼容构建中 WebGPU Worker、WASM 打包及模型缓存是否真正运行；类型检查不是模型运行证据。
- 此处未解决：平台播放器受限制、加密内容或无法获取可靠媒体时钟时的完整支持矩阵；默认明确提示不可用，保留已有字幕阅读。

### e) 验收剧本

验收剧本 1：在参考 Mac 和 Windows 的 Chrome 打开真实无字幕 YouTube 视频，进入学习页并开启生成与中文翻译，观看 20 分钟。播放器可听、文稿持续增长、字幕覆盖层不因翻译晚到而空白；记录实际捕获 tab、原文/译文时延、资源曲线、导出 TXT 与屏幕录像。分别测试主授权和共享兜底，拒绝授权后视频仍正常。

验收剧本 2：在真实 B 站无字幕视频执行暂停、缓冲恢复、前后跳转、1.5× / 2×、分 P 切换。时钟失联时暂停生成；跳转后的旧事件不得落到新位置；不同分 P 缓存隔离。用 eventSeq / epoch 日志、人工标注时间、两份导出文稿验证，不以按钮可点击代替验证。

验收剧本 3：准备已有模型但没有 translationModel 字段的旧配置，打开平台字幕视频并翻译，再开启生成字幕并等待平台字幕晚到。旧翻译仍有可用模型；只有一个当前来源；复制和 AI 只包含选中来源的稳定原文。关闭翻译后旧请求晚到不重新显示，重开可复用匹配缓存；比较请求次数与本地存储快照。

验收剧本 4：故意使推理落后、翻译超时、模型下载中断或页面刷新。待处理队列不能误删执行中任务之外的窗口，达到上限明确暂停并记录缺失；翻译失败原文仍保存；刷新后稳定文稿恢复，取音不会自动重新开始。用故障注入、存储核验与控制台日志验证。

验收剧本 5：对生成到一半的视频点击复制、下载和 Obsidian 剪藏，再写一条学习理解。输出仅包含固定快照，保留覆盖范围与来源；译文未齐时有明确提示；日记追加只出现一次，Native 落盘后才显示成功。核查实际 TXT / Markdown、Vault 内文件与日记，而非只看 toast。
