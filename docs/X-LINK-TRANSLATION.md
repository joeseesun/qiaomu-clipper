# 在对话框翻译 X 长文章

在乔木剪藏 AI 对话框粘贴 X 分享链接。只有链接时默认逐段译成简体中文；也可以写「完整翻译成中文 + 链接」或指定其他语言。「不要翻译，分析这篇」会将原文交给当前选择的模型回答。一次最多 3 个链接。

原文卡片显示实际读取的字符数，支持下载 Markdown 原文。译文由对话框当前选择的模型生成，沿用该服务商的费用与配额；Grok 订阅用于必要时的链接定位，并不自动替代当前翻译模型。每批译文必须包含全部段落；失败、超限或取消不会标记为全文完成。代码块逐字保留，图片保留原地址，内嵌帖子保留链接。图片内文字、视频和内嵌帖子的正文不包含在这次文字翻译中。

## 按需启用，每台电脑设置一次

普通网页阅读和剪藏不要求启用 X。设置 →「可选功能」始终保留「X 完整阅读」入口；打开说明不会联网检测或下载。用户选择「检查连接并设置」后，才检查 Grok 下载服务，并按当前电脑的缺失状态引导安装助手、下载组件和官方网页登录。网络不通时可选择「暂不启用」，继续其他功能。

macOS `.pkg` 与 Windows `.exe` 包含独立 Python，不要求普通用户安装 Python、配置命令行或手动执行登录命令。需要扩展与本次助手 1.16.13 配套；X 读取不依赖 Obsidian 笔记库。换电脑重新安装、检测和登录，不复制令牌。

本 PR 提供构建源码与未发布状态下的明确提示；正式下载地址需维护者完成签名、版本资产上传后启用，不会链接到缺少 X 功能的旧版本。开发诊断及发行步骤见 [助手安装与发行](../native/X-HELPER-SETUP.md)。Linux 保留源码安装能力，本次未提供图形安装包。

Windows x64 无系统 Python 环境已验证安装、升级、卸载、重装及离线功能；Windows X/Grok 下载、登录和联网全文读取仍待测。详见 [Windows 验证边界](verification/windows-helper.md)。macOS 的成功样例不代表所有平台与全部 X 页面均可访问。

## 实际读取机制

1. 本地助手请求 X 原网页，解析网页自身的结构化正文。只解码数据，不执行网页 JavaScript，不以标题、预览、搜索摘要或模型复述充当原文。
2. 原网页不返回正文时，由已登录的 Grok CLI 使用 X 搜索定位至多 3 个原帖地址。再次读取 X 原页面，并核对帖子或文章 ID。不同文章、回复、引用不能替代目标原文。
3. Article 的 `plain_text` 会遗漏代码等原子块，因此读取 `content_state`、`entity_map` 和媒体字段。未知或缺失结构会显式失败。每份正文有 SHA-256；扩展分批接收并核对哈希，再送入当前模型。
4. 默认一次请求提交一篇文章的全部待译正文，不再按 8 段／6,000 字符分批，也不切割 1,800 字符以上的段落。段落 ID 只用于检查覆盖、顺序和恢复版式。代码、链接标记丢失会整篇重试一次，仍不合格就停止。
5. 只有模型服务明确报告上下文超限或输出截断时，才缩小请求范围。网络、账号、配额和内容错误不会触发拆分重试。单段过长时可在安全边界拆开；仍无法处理则保留已确认部分并明确报错。结构校验能防漏段和意外截断，不能证明模型的语义翻译完全准确。

## 模型原生长度

普通对话不再裁掉 80,000 字符之后的正文、4,000 字符之后的引用或第 40 条之前的历史；写作区的正文、选中内容、参考正文和当前会话也完整保留。没有通过摘要替换或悄悄删除历史来适配小模型。实际请求超过服务上下文时会报错。

扩展取消固定的 8,000 输出 token。优先读取当前服务商模型目录中明确的输出上限，不能把上下文长度当作输出上限；目录没有公布时使用服务默认值。DeepSeek 官方当前文档明确给出大输出上限的对应别名使用文档值。自定义服务可在「编辑模型 → 最大输出 token」中填写其文档允许的值。Anthropic 协议要求这个参数，自动读取失败时会要求配置，不会伪称已恢复最大输出。

Ollama 不再强制 32,768 上下文，沿用本机 Ollama 配置；可在模型设置中明确填写上下文。机器内存和服务配置仍决定能分配多大窗口。账号 OAuth 接口沿用服务端设置，不强塞不支持的参数。

输入容量、单次输出容量、服务默认值是不同概念。恢复完整输入不等于无限输出，也不能覆盖服务端上限、套餐配额或网关限制。详见 [模型长度说明](MODEL-CONTEXT.md)。

当前实测的 Grok CLI 1.0.41 不把 X 工具的完整原始结果导出给 ACP 客户端，Grok Bot 的帖子 API 对此样例也只返回标题及短文。它们不能单独证明 Article 全文已获取。因此本实现使用 Grok 定位 + X 原页面核对的组合，不把 Grok 回答冒充原始下载结果。官方资料：[CLI](https://docs.x.ai/build/cli/headless-scripting)、[X Search](https://docs.x.ai/developers/tools/x-search)。

## 限制与恢复

- 只处理公开且当前可访问的 HTTPS X/Twitter 帖子、长帖、文章链接；不绕过登录、私密访问或平台限制。网页格式变化可能需要更新解析器，失败时不会用截断文本继续翻译。
- 单篇正文上限 500,000 UTF-16 字符，页面上限 8 MiB。超限明确停止。线程只读取目标帖子，不自动拼接整串回复。
- 原文与读取日志保存于本机助手的 `x-articles/`，新任务启动时清理超过 7 天的旧任务。历史卡片到期后需重发链接。分享聊天记录不会携带整篇缓存文件。
- 不要求打开 X 界面，也不依赖浏览器是否已登录 X；公共页面仍受网络、地区、平台限流与可用性影响。若定位需要 Grok 而未登录，会显示设置入口并引导官方网页登录。
- 后台一次只读取一个任务，重复启动同一任务不会多次调用 Grok；停止会取消后台读取。没有任何浏览器页面可传入任意命令、可执行文件路径或提示词。
