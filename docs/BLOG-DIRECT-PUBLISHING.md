# 博客直接发送 X / 知乎草稿

博客编辑器发送菜单 → X 文章或知乎 → 发送草稿。扩展自动打开对应平台，复用原有适配器写入图文草稿，并向博客返回进度与结果。不运行本机服务，不填写端口、不请求本地网络权限，也不读取平台密码。需要浏览器已有目标平台的登录会话。

网页通过 `qiaomu-web-publish-v1` 的同窗口消息交给隔离世界脚本，再通过 runtime 消息进入后台。静态脚本仅注入 `https://blog.qiaomu.ai` 与本地开发地址。后台重新验证发起页来源及顶层 frame，按来源标签页隔离任务，校验资源 ID、字节数、MIME、数量和总大小，只允许 X / 知乎。网页不能指定执行代码、目标任意地址或读取其他页的任务。图片来自页面交接的字节，扩展不会按网页传入的 URL 任意抓取资源。

网页后台轮询和适配器 heartbeat 均会调用实际扩展 API；取消会沿用既有适配器的 cancel。来源页关闭、平台页关闭、超时、扩展重启均可终止或返回明确错误，不会自动重复创建草稿。终态任务清理资源。现有 Obsidian 回环协议仍可使用。

本版本不更改原有文章正文、公开发布或接管用户登录。博客将发送副本中的音视频和 iframe 转为原内容链接；来源无效时保留媒体占位说明。

验证：`npm test`、`npx tsc --noEmit`、`npm run build:store`、固定测试入口 `npm run test:prepare`。浏览器重载与平台实际写入另行验收。

## MP4 与长文发送进度

博客发送到 X 时会读取文章 MP4 视频文件并作为 `video/mp4` 资源传给适配器，不再把没有交接文件的裸 MP4 链接交给视频检测器。当前传输保护为视频单项 32 MiB、全部资源合计 40 MiB；超过容量或读取失败时保留带行内说明的链接，并在博客明确提示降级数量，不假装已经上传。此保护值不是 X 平台的上传上限。

知乎写作页在创建草稿、上传每一张图片和写入正文期间显示进度，完成后才自动打开已保存的完整草稿，避免长文看上去一直是空白页。不会自动公开发布。

## 长文收尾检查

实际长文（图片、GIF、多个 MP4 引用）暴露了收尾时序问题：清理占位符后，立即用 React 尚未提交的旧 editorState 强制刷新，会把清理前的状态写回。收尾现在等待状态提交后重新取当前编辑器，并验证正文没有本轮占位符、所有已上传的正文媒体块仍存在；没有通过检查就不能报告成功。回归测试在旧引擎上可复现失败。
