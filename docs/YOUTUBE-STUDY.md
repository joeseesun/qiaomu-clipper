# YouTube 沉浸学习（1.8.0）

YouTube 视频页的 `aaa` 快捷键进入剪藏草稿的阅读预览。旧版将正文经过 Markdown 转换和 HTML 清理后渲染，播放器 iframe 与字幕结构信息丢失，结果只有视频说明和文稿。

新版在渲染后的文章中根据原始 YouTube URL 恢复播放器，仅接受 YouTube 官方域名及合法视频 ID；恢复 Markdown 字幕的时间戳、字幕行样式与播放跳转元数据。播放器位于文稿上方，视频说明保留在文稿之后。Chrome 播放器在 Referer 规则安装后重新加载，避免从 0:00 打开的草稿先发出缺少 Referer 的嵌入请求。

文稿工具栏支持复制带时间戳的字幕、下载 UTF-8 TXT，以及打开基于字幕的 AI 对话。字幕导出排除视频描述、章节标题和阅读器按钮。AI 沿用现有模型设置与对话历史；草稿预览使用字幕作为上下文。原页沉浸模式的 AI 请求通过扩展后台流式转发，停止对话会断开连接并取消后台请求。没有取得字幕时显示状态并禁用文稿操作，可先打开 YouTube 原页转写面板再重试。

## 验证

- 回归测试覆盖 Markdown 播放器恢复、合法域名/ID、字幕时间戳还原、复制/下载与 AI 上下文一致性、无字幕状态、避免重复播放器和工具栏、后台流式转发与取消。
- 类型检查与 Chrome/Firefox/Safari 构建作为发布检查。
- Chrome 已安装扩展已重新加载到 1.8.0；`aaa` 打开草稿预览的链路已观察到。
- 完整的修复后播放、跳转、导出和 AI 实际响应验收仍待完成：自动浏览器策略禁止直接导航扩展内部 URL，已请用户从视频页打开新版阅读预览。此记录不将构建或 iframe 恢复测试视为实际播放成功。

## 1.8.1：播放器优先、字幕异步加载

旧快捷键先打开剪藏弹窗，等完整提取后消费待执行阅读指令；该指令在 15 秒后过期，字幕加载较慢会停留在弹窗。新版在 YouTube 视频页按 aaa 时，直接创建学习阅读页；普通网页和编辑/剪藏快捷键沿用原流程。

学习页先渲染播放器，然后读取原视频页当前 DOM 并异步提取字幕；原页仍在加载字幕时，不影响播放。每次提取最多等待 20 秒，超时或无字幕显示可见状态和重试按钮。重试重新读取源页面，不刷新播放器。文稿成功后附加时间轴与 AI/导出工具，最后启用剪藏按钮，避免保存加载占位文案。实际浏览器加载与播放验收仍待用户确认；自动浏览器策略禁止访问扩展内部页面。

## 字幕为什么常常读不到，现在怎么取（2026-10-03）

**原因**。官方 clipper 在 YouTube 页面里直接运行 Defuddle：用页面自己的 `fetch`（带 YouTube 的 cookie 和来源），读取页面已有的数据，不行再点开页面上的转写面板读取。学习页原来是在扩展页里拿一份静态 HTML，再通过后台代理去抓字幕文件：请求没有 YouTube 的会话，也没有页面上的播放器令牌，静态副本里还打不开转写面板，所以 YouTube 返回空内容时就没有任何兜底。

**现在**。三条路同时/依次取，谁先拿到字幕用谁：

1. **原页提取**（新）：后台让视频所在标签页里的内容脚本执行与官方 clipper 相同的 `getPageContent`（页面 `fetch` + Defuddle 的面板兜底）。
2. **原页转写面板**（新，兜底）：第 1 条仍没有字幕时，在原页点开「转写文稿」，直接读取 YouTube 自己渲染出的字幕行（它是页面用你的登录会话请求的，不受字幕文件限制影响）。
3. **静态副本 + 后台代理**（原有）：原页不可用（标签被关）时仍能工作。

三条都失败才提示「暂未获取到字幕」，此时按提示在原页打开转写文稿再重试。B 站同样先走原页提取，登录会话天然生效。

**限制**。原页提取会在你的视频页里点开转写面板（与官方 clipper 的兜底行为一致）；YouTube 改版转写面板的结构时，第 2 条需要跟着更新（解析逻辑与「复制 / 下载」按钮共用）。本机无法登录真实账号验证，只用单元测试和结构探查核对，未在真实视频上跑通。

### 为什么要重试好几次（已修）

重试一两次才成功，是因为第一次其实在「预热」页面，而不是真的失败：

1. 按 `aaa` 后立刻开始取，此时 YouTube 的描述区和转写面板还没渲染完，找不到「显示转写文稿」按钮，兜底直接放弃；
2. 字幕文件请求要等 4 秒级的超时才会失败，两三个请求叠加后撞上总时限，第一次整体超时；
3. 超时时原页里的提取并没有停，它顺手把转写面板点开了——所以第二次读到的是现成的字幕行，一下就成功。

现在的顺序：

- **先开面板再提取**：后台先让原页等待并点开转写面板（按钮还没出现就等，不重复点击已展开的面板以免关掉；面板停在「章节」页会自动切到「转写文稿」），字幕行渲染出来后再执行完整提取，此时 Defuddle 直接读页面上的字幕，不再靠网络和超时。
- **自动补一次**：第一次没拿到时，静默等 1.5 秒再试一次，才显示「重试」按钮。
- **总时限放宽**：20 秒→35 秒（原页提取最长 28 秒）。

### 入口卡片与字幕预取

不再等 YouTube 懒加载转写面板：

- **入口卡片**：视频页右侧栏最上方常驻「乔木 · 沉浸学习」卡片（沉浸学习 / 复制 / 下载），不依赖转写面板，页面一加载就在；设置里「YouTube 转写文稿按钮」同时控制它和面板里的三枚按钮。
- **预取**：页面空闲后（以及站内切到下一个视频后）在 YouTube 标签页里请求一次 `/youtubei/v1/next`，取出 `getTranscriptEndpoint`，再调 `get_transcript` 拿字幕行并缓存；按 `aaa` 或点卡片时直接用缓存，学习页只需要从页面副本读标题和简介（不走网络），不再等任何超时。
- **兜底不变**：预取没有结果时，依次走「点开转写面板读取」和原来的整页提取；卡片状态为「点击后读取字幕」。
- **已知限制**：在未登录的会话里实测 `get_transcript` 返回 400（Precondition check failed，YouTube 要求播放器令牌）。预取连续两次被拒绝后，本页不再重复请求，直接走面板兜底；已登录账号下是否可用本机无法验证。解析函数、请求顺序和降级逻辑有单元测试。

### 自动展开转写面板

YouTube 默认不展开右侧的转写文稿面板；以前要点一下插件图标，提取器兜底时顺手点开它，面板里的按钮才出现。现在视频页空闲后会**自动展开一次**（设置里「自动展开 YouTube 转写文稿」，默认开启）：

- 每个视频只展开一次；你关掉之后这个视频不再自动展开，切到下一个视频才会再来一次。
- 面板里渲染出的字幕行同时作为「字幕已就绪」的来源，复制、下载和学习模式直接使用，不再等预取接口（未登录时它会被 YouTube 拒绝）。
- 页面结构里还没有「显示转写文稿」入口时不做任何事，等页面渲染到之后再试，不会反复点击。

### 转写面板里的按钮：位置与点击

- **位置**：按钮不再塞进「章节 / 转写文稿」的横向滚动条，而是紧贴在滚动条下方单独一行。滚动条里窄面板会把按钮裁掉、把键盘焦点环切成半圈弧线；它还用拖动来滚动，可能截走点击。
- **点击**：按下时不让事件冒泡到滚动条，并在抬起时直接触发动作（紧随其后的 click 去重），所以滚动条抢占指针也不影响；鼠标不再显示焦点环，只有键盘 Tab 才显示且画在按钮内侧。
- **失效提示**：扩展刚更新过、页面还是旧的脚本时，点「沉浸学习」会提示「请刷新此页面」，而不是毫无反应。

### 转写条（取代入口卡片和面板里的按钮）

参考 YouTube Summary 之类的助手：视频页右栏最上方一条常驻的横条，**不依赖转写面板，也不需要点插件图标**。

```
[书本标] 乔木 · 沉浸学习 ●        [字幕] [复制] [下载] [沉浸学习] [设置] [⌄]
```

- **五个按钮**：字幕（展开并加载字幕列表）、复制、下载、沉浸学习、设置（打开扩展设置 → 常规）；最右的箭头或点击横条本身展开 / 收起下拉，展开状态记在本页的 localStorage。
- **下拉**：状态行（正在准备 / 字幕已就绪，点击时间可跳转 / 点击后读取字幕）加字幕列表。列表按段落合并，点时间让当前视频跳到该处；最多显示 400 段，更多请进沉浸学习。
- **状态点**：橙色闪烁 = 准备中，绿色 = 已就绪，灰色 = 还没取到。
- **字幕来源**：预取、YouTube 自己渲染的转写面板（自动展开后读取），两者谁先有用谁；复制、下载、展开字幕都会等到有字幕或超时才给结果。
- **失效处理**：页面是扩展更新前打开的，点沉浸学习会提示刷新；按下事件不传给页面，抬起即触发，避免被 YouTube 的拖动滚动吞掉点击。
- 设置里「YouTube 转写文稿按钮」控制这条是否显示，「自动展开 YouTube 转写文稿」控制是否自动展开面板。原先在面板标签栏旁的三枚按钮和独立的入口卡片已删除，避免重复。

### YouTube 自带的转写面板（右栏「在此视频中」）

那是 YouTube 自己的面板，不是我们做的。我们只在「自动展开」时帮你点开它——为了让 YouTube 把字幕行渲染出来作为兜底字幕来源。现在有了转写条，这个面板是重复的，所以：

- **自动展开后把它隐藏**（设置里「隐藏 YouTube 自带的转写面板」，默认开）：用 `display:none` 藏起来而不是关掉，字幕行仍在页面里，转写条、复制、下载和学习模式照常读取。等字幕行渲染好（最多 6 秒）才隐藏，不会饿死兜底。
- **只藏我们打开的**：给它打上 `data-qiaomu-auto` 标记才会隐藏；你自己点「显示转写文稿」打开的面板永远不隐藏，关掉之后标记也会清掉。
- 不想要自动展开：关掉「自动展开 YouTube 转写文稿」即可，此时转写条里的字幕靠预取或首次点击时再读取。

### 转写条的搜索、跟随高亮与点击跳转

参考阅读模式（`reader-transcript.ts`）的做法，并对照常见的字幕 / 歌词跟随体验：

- **点击跳转**：点任意一段，视频立刻跳到该处，并马上把它标成当前行、恢复跟随。
- **跟随高亮**：监听页面里视频的 `timeupdate` / `seeked` / `playing`（捕获阶段监听，视频元素被 YouTube 替换也不丢），二分查找当前行，只在行变化时更新。当前行有蓝色竖条和底色、字重加粗。贴片广告在同一个 video 元素上播放，播放广告时忽略。
- **滚动策略**：默认跟随。当前行仍在列表中间区域（15%–70%）时不动，离开后平滑滚到约三分之一高度处；已经就位不重复滚动；尊重系统「减少动态效果」。
- **让位给用户**：在列表里滚轮、触摸、按下滚动条后暂停跟随 2.5 秒（与阅读模式的 2 秒冷却同一思路）。当前行不在可视区时出现「回到当前位置」按钮；搜索时不自动滚动。
- **跟随开关**：搜索框右侧的定位按钮，开关状态记在本页的 localStorage。
- **搜索**：输入即过滤（停顿 100 ms），匹配词高亮、显示条数、「无结果」提示；清除按钮或 Esc 恢复，并回到当前行。大小写不敏感，中文直接子串匹配。搜索框拦截 keydown / keyup / keypress，避免 YouTube 的单键快捷键（空格、k、f…）在输入时触发。
- **首次展开**：直接定位到正在播放的那一行，而不是列表顶部。
- 上限 1500 段，超出的请进沉浸学习查看。沉浸学习页自身的字幕（阅读模式）原本就支持跟随和点击跳转，搜索目前只在转写条里。

### 学习页字幕的搜索

沉浸学习页的字幕（阅读模式）原本就有跟随高亮和点击跳转，现在加了搜索：字幕上方一条平实的搜索框（只有一条细底线，没有背景和卡片），输入即过滤（停顿 100 ms），章节标题在其下没有匹配行时一并隐藏，右侧显示条数，`×` 或 Esc 清除。匹配词用 CSS Custom Highlight API 标出（与播放高亮同一种机制），不改写文字节点，双语译文也能搜到；时间戳不参与搜索。搜索期间不自动滚动，清除后恢复。

### 当前行的样式（不要用卡片加左侧竖条）

转写条里当前行只靠字体区分：当前行全对比度、字重加粗，时间加粗；其余行字色退一档（搜索时不退），不用底色、不用侧边竖条、没有圆角。圆角底色加蓝色竖条是最典型的「AI 味」样式，已被明确否决。
