# 在线图文问答验收

2026-10-12，本地构建 `dist_local`，Ego/Chromium 加载的扩展。

## 使用

1. 保持原网页打开，通过阅读入口（默认连按三次 A）进入阅读页。
2. 打开 AI 对话，使用自己配置的支持图片输入的模型。
3. 默认随问题读取正文图片；展开“图片”可选择部分图片、“问图 N”或“仅正文”。回答里的图片编号可定位原图。

图片在提问时获取、压缩并以实际图片内容发送。无需安装本地助手或保存到 Obsidian。已处理图片仅在当前页面内存中缓存；对话历史只保存文字与图片编号。关闭页面后重新提问需重新取得图片。浏览器自身仍可能使用其 HTTP 缓存。

每轮最多选择 16 张图；长图切块，总计最多 32 块、约 20 MiB 序列化图片数据。超限明确报错，不悄悄丢弃后面的图；部分读取失败显示失败编号，全失败不发送纯文字冒充读图。服务拒绝图片时保留问题并提示换模型或减少图片。

## 已验证

- 全量 Vitest：122 个文件、1,069 项通过；最后入口与问答调整后相关 28 项通过。TypeScript 类型检查通过，本地生产构建通过（3 项既有体积提醒）。
- 真实 DeepSeek 请求：通过已有 aigocode-team 服务调用 `deepseek-v4.1-flash`。临时本机代理仅为测试转发，凭据未写入扩展设置；代理和临时配置在验收后清理。
- 自制视觉样本：蓝色三角形 731、橙色圆形 286，以及 900×5000 长图上的 TOP 194 / MIDDLE 582 / BOTTOM 637 均识别正确。3 张源图实际发出 6 块，包含长图底部。
- 用户提供的小红书笔记 `6acb9de3000000001b02fef7`：原站阅读快捷键→解析→阅读页→AI 对话。仅提取 3 张正文图，顺序正确，无推荐图、轮播副本、头像或评论。
- 小红书三图请求实际发出 3 块，尺寸为 1036×828、1080×1132、1286×1080，服务 HTTP 200。模型正确区分人物照片、攀岩现场与文字报告，并读出正文没有的报告文字和数字；已对照原图。模糊小字并非均可确认，不能据此承诺 OCR 百分之百准确。
- 点击回答的图3链接能定位第三张原图；选择“问图3”后下一轮仅发出 1 块，正确抄录指定行。真实存储检查确认对话记录无 `data:image/`。
- 原网页图片读取桥实测返回有效像素；它限定当前原页已有图片，不导出 Cookie。浏览器可显示跨域图片并不保证 Canvas 可读取，获取失败仍需明确提示。

## 实测中修复

- 小红书图集限定详情容器，去除 Swiper 克隆，按 slide index 排序。
- 内嵌面板使用消息来源的 `sender.tab`，避免多窗口时误取其他窗口的活动页。
- 图片上下文不再把 Base64 或签名图片地址塞进正文文本。

## 验收边界

OpenAI Chat Completions / Responses、Codex OAuth、Anthropic、Gemini、Ollama 的图片请求结构已有自动化覆盖。本次真实服务测试仅涵盖上述 DeepSeek 通道；GLM 5.3 Flash 和其他 OpenAI 模型未做真实调用，不能按品牌假设所有模型或转接服务支持图片。没有发布商店更新，也没有提交或推送 Git。
