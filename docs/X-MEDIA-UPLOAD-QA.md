# X 文章 GIF / MP4 导入修复（2026-10-21）

用户确认：GIF 已上传，但导入停在第 22/25 项并误报超时。该反馈不能归因为限流；此前通用超时文案没有限流证据。当前只读工具未能取得真实 Draft 实体数据，不能把 VIDEO 类型或某个字段当成这一次故障已经证实的具体原因。

## 代码证据与处理

- 旧识别只接受 MEDIA，不能读取 Map/Immutable 数据；递归搜索任意数字，会把时长误当媒体 ID。现在识别视频/GIF 媒体类型、读取集合、仅搜索媒体身份字段；已有块换实体键不算当前新上传。
- 原生 INIT 得到 ID 不代表处理完成。导入期间临时观察 X 原生 fetch/XHR 的媒体上传响应，区分 INIT、FINALIZE、STATUS 和 processing_info；按实体 ID 或唯一匹配的文件大小/MIME 关联。未知、多个候选不盲猜，blob 预览不作为成功证据。
- 不发送额外上传/状态请求，不读取请求头、Cookie 或凭据，不输出原始网络内容。返回值与原生响应保持原样；完成、失败、取消后恢复自己的包装函数并移除监听。实际网站是否全部通过这些原生入口仍需现场核验。
- 静态图保留 90 秒上限；GIF/MP4 含转码阶段，有 10 分钟硬上限和阶段反馈。失败立即停止，不重复上传；无法确认时提示先检查草稿，保留格式与有限字段名用于诊断。
- MP4 直接链接、独立 Markdown 链接、图片语法引用和 HTML video/source 块走文件上传。媒体计划保持原顺序；阅读转写作保留直接 MP4 链接。iframe、blob、HLS/DRM 不作为可下载 MP4 文件承诺。
- 当前跨扩展消息使用 base64，单个 MP4 限制为 32MiB，避免超过 Chrome 单消息预算；GIF 超过 15MiB 拒绝而不静默截为单帧。视频/GIF 不作为自动静态封面，显式选作封面会在改远程草稿前提示。

## 参考与取舍

## 停止、重试与原草稿续传（2026-10-21）

- 写作页和 X 状态卡均提供停止；错误/停止卡持续保留，关闭或连接失效后才移除/禁用恢复动作。失败后可选择「继续剩余」或「重新写入」；后者强制新建草稿并保留旧稿。
- 停止覆盖准备媒体、打开页面、注入、连接、表格渲染和 MAIN 写入。桥接等待 MAIN 清理确认再结束，不提前把下一任务送入忙碌引擎；10 秒收不到确认时明确提示先检查草稿，不假称完成。原生上传已交给 X 后，平台仍可能继续处理该项。
- MAIN 在正文和特殊块写入后建立页面内断点，记录源内容、草稿 ID、已确认媒体身份、未完成标记和当前上传阶段。续传先核对正文/格式/链接、已完成媒体和草稿身份，跳过已确认成功的操作，不重写正文和标题。
