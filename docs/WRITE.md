# 写长文

在任意网页连按 3 次 U（可在设置里改键），或在设置的「写长文」里点「新建文章」，进入所见即所得的 Markdown 编辑器。文章和图片都保存在这台电脑的这个浏览器里。

## 它是什么

- **文章列表**（设置 → 创作 → 写长文）：新建、搜索、复制、导出、导入 `.md` / `.zip`、移到回收站（30 天内可恢复）、彻底删除、导出全部。
- **编辑器**（`write.html`）：
  - 标题、大纲、字数；`/` 命令菜单；选中文字后的浮动工具栏；每个段落旁的「+」和拖动手柄（转换、复制、上移下移、删除、设为封面）。
  - 标题 1–3、粗体、斜体、删除线、行内代码、链接、引用、列表、待办、表格、分割线。
  - 代码块（语法高亮）、Mermaid 流程图、`$行内公式$` 与 `$$公式块$$`（KaTeX）。
  - 图片：粘贴、拖入、选择文件；拖右侧把手调宽；网页图片可「保存到本地」。
  - X 推文与 YouTube / 哔哩哔哩 / Vimeo 链接单独一行即成卡片。
  - Markdown 源码切换。
  - **大纲**：参考飞书文档，在文章右侧显示标题和各级标题，当前读到的一节用蓝色标出；收起后是一列短横线，指上去展开。
  - **AI**（用设置里已有的 LLM 模型，结果都先预览、你接受才改文章）：
    - 选中文字后：润色、缩短、扩写、总结、译成英文/中文、按我的要求改，以及你在设置里添加的**自定义快捷指令**。
    - 续写；标题旁的「让 AI 起标题」、摘要旁的「AI 写摘要」。
    - **AI 助手**（顶栏 AI 或 ⌘/Ctrl+J），参考乔木 Agent 的对话：
      - 看得到整篇文章和**选中的文字**（输入框上方的「选区」标签，可取消；选了文字时快捷条自动换成针对选区的提示词）。
      - 可以附上图片（粘贴、拖入、选择）、公开网页（只读正文）和**文库里的其他文章**（输入 `@` 选择）。
      - 每个模型可选**思考强度**（自动 / 低 / 中 / 高，按模型而定），回复里显示「已思考 N 秒」和思考过程。
      - **提示词库**（输入 `/` 或点「提示词」）：场景提示词、乔木精选、Yao Open Prompts 和你自己的；支持 `{{空白}}`、`{selection}` 等占位符、固定到快捷条、导入导出。
      - 它不确定时会用选项卡片问你，点一下就把答案发回去。
      - 提出的改动（改标题、写摘要、插入、替换某段话、生成配图）是卡片，逐条「应用」，也可以「撤销」；回复本身可以「放进文章」（光标处 / 文末 / 替换选区），也可以复制、重新生成、编辑后重发。
      - 对话按文章保存，删除文章时一并清除。
    - **AI 配图与封面**：`/` 菜单里的「AI 配图」、助手建议的配图、文章信息里的「AI 生成封面」，都用设置里的生图模型。
  - 自动保存；同一篇文章只允许一个标签页编辑。
- **发到 X 文章**（发布 → 发到 X 文章）：在你已登录的 X 里新建一篇文章草稿并写入标题、正文、图片、表格和封面，由你在 X 里检查后自己发布。

## 生图模型

设置 → AI 模型设置 → 生图模型，参考乔木封面设计插件：先选来源，再点「获取可用模型」列出该服务支持的所有生图模型（OpenRouter 和 Gemini 直接给出生图模型，OpenAI 兼容服务按名称筛选），勾选要用的，第一个是默认。生成配图或封面时，在窗口里按「服务 · 模型」任选。\n\n来源有：**ChatGPT / Codex 账号登录**（沿用「LLM 提供商」里已登录的账号，不需要密钥；ChatGPT 账号走 OpenAI Images API，Codex 账号走 Codex 后端的内置绘图工具）、豆包 Seedream、Google Gemini（Nano Banana）、OpenAI、OpenRouter、SiliconFlow、智谱 CogView，以及任何 OpenAI 兼容的 `/images/generations` 接口。密钥只存在这个浏览器的本地存储里，不同步。没有实现 Codex CLI 那条本机命令行通道。

## 数据

IndexedDB `qiaomu-write`：`articles`、`images`（按内容哈希去重）、`meta`。Markdown 是唯一真源，本地图片在正文里写作 `qm-image://<id>`。导出时换成 `assets/<id>.<ext>` 并写 front matter（title / author / digest / source_url / cover）。没有任何文章或图片被上传到服务器。

文章有 `publishes.{x,wechat}`，记录各平台的发布时间、链接和远端 id，为「再次发送时更新而不是新建」预留。`author`、`digest`、`sourceUrl`、`coverImageId` 与乔木发布插件（公众号）使用的属性一致。

## 发到 X 的实现

引擎改编自 xPoster（MIT，见 `THIRD_PARTY_NOTICES.md`），保持与原版接近，方便把 X 页面变化的修复带过来：

1. 写作页把文章整理成 X 引擎读的 Markdown（`src/write/publish/x-prepare.ts`）：图片换成稳定地址，Mermaid 与公式块渲染成 PNG，行内公式变成行内代码，待办框变成符号。
2. 写作页把每张图读出来（svg、bmp 或过大的会重画），通过端口交给 X 标签页，因为 X 页面读不到扩展的本地库。
3. 只在发布时向 X 标签页注入两段脚本：`x-publish-main.js`（页面世界，操作 Draft.js）和 `x-publish-content.js`（隔离世界，接收文章、驱动流程）。不常驻、不在 manifest 里声明。
4. X 页面里已有空白编辑器就复用，否则新建一篇；写完后停在 X 页面等你检查。

限制：X 文章没有公开的图片数量上限，沿用 xPoster 的稳妥值 25（图片 + 表格 + 图表 + 公式块 + 封面）。每次发送都会在 X 新建一篇草稿，不会更新旧的。X 改版时，先看 `src/x-publish/adapter.js` 的选择器与 `main-world.js` 的 Draft.js 操作。

## 未来：公众号

沿用同样的形状：`Publisher`（`src/write/publish/types.ts`）负责把文章转成目标平台的内容。公众号发布参考 Qiaomu Publish（Obsidian 插件）：Markdown → 带主题的公众号 HTML（内联 CSS）→ 上传图片 → 创建草稿，连接方式为乔木中转 / 直连微信 / 自建 Bridge。公式与流程图已有 `src/write/render-assets.ts`，可直接复用。

自动检查：数据层、Markdown 往返、导入导出、AI 面板与助手、生图窗口与各家生图接口的请求、大纲、斜杠触发、设置页路由、X 内容脚本接线、X 前的 Markdown 整理、界面规则、九种语言文案。在模拟扩展 API 的浏览器页里看过：编辑器、`/` 菜单、浮动工具栏、块菜单、图片粘贴、公式、Mermaid、表格、推文与视频卡片、设置里的列表与回收站、浅色和深色，以及发布流程（含图表和公式转图片）的整条链路。
